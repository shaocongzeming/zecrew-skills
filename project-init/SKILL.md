# Project Init — 建上下文入口

你的核心交付物**不是文件夹**,是一份「项目开发日志.md」——fresh agent 进入项目时,读完它就能直接开干。其他文件(CLAUDE.md / AGENTS.md / README / 目录结构)都是这份日志的辅助。

ai-os 标准加载组合是 `INDEX.md + 项目开发日志.md`(见 `/Users/sunshaocong/.ai-os/INDEX.md` 第 29 行)。你的产物必须让这个组合成立。

<HARD-GATE>
在「冷启动模拟」通过之前,不要宣告交付完成。
冷启动模拟即:你扮演新 agent,只读刚生成的日志,回答三问。任一答不上,回去追问用户补字段。
</HARD-GATE>

## 触发后第一步:环境扫描 + 模式判断

并行扫描三件事:

```bash
# 1. 当前目录是否已在某个项目里(存在「项目开发日志.md」)
test -f ./项目开发日志.md && echo "ALREADY_IN_PROJECT"

# 2. cwd 或 ~/Desktop 是否有 Prompt-*.md(idea-to-prompt 的输出)
ls ./Prompt-*.md /Users/sunshaocong/Desktop/Prompt-*.md 2>/dev/null

# 3. 桌面已有项目编号(排除 00 和 99)
ls -d "/Users/sunshaocong/Desktop/MacBookpro备份内容/"[0-9][0-9]_* 2>/dev/null \
  | grep -vE '/(00|99)_' | sort
```

根据扫描结果自动判断模式:

| 扫描结果 | 模式 | 默认行为 |
|---------|------|---------|
| cwd 已是项目根(有日志) | **B 补建 / C 刷新** | 检查缺失文件 + 日志最后更新日期 |
| cwd 不是项目根 + 有 Prompt-*.md | **A 新建+接力** | 读 Prompt,跳过大部分追问 |
| cwd 不是项目根 + 没有 Prompt | **A 新建** | 走轻量追问 |

模式不明显时,用 AskUserQuestion 让用户确认。

## 模式 A:新建

### A1. 信息收集(优先读 Prompt 文件)

**有 `Prompt-*.md`**:
- 直接 `read` 该文件
- 从中提取:项目名 / 项目类型(四类之一) / 一句话描述 / 目标用户 / 技术栈 / 不做的事 / 风险
- **只问差量**:Prompt 里没有的「项目编号建议」「项目根目录中文名」补问

**没有 Prompt-*.md** — 轻量追问,3-5 问,一次一问:

| 必问 |
|------|
| 项目叫什么?一句话说清楚是什么 |
| 是哪一类?开发 / 长内容 / 视觉素材 / 策划 |

| 按类型追问(每类选 1-2 个) |
|------|
| 开发类:目标用户?平台(网页/小程序/桌面)?有没有技术偏好? |
| 长内容类:给谁看?什么调性?最终格式(PPT/PDF/Word/图)? |
| 视觉素材类:用途?成片数量?目标 AI 工具(MJ/Sora/...)? |
| 策划类:什么时候落地?大概多少资源 / 多少人? |

用户说「够了」立刻停。

### A2. 项目编号 + 命名

基于第一步扫描结果,用 AskUserQuestion 给三个选项:
- 建议编号(max + 1)
- 中间空位(如有 02、04 缺 03,补 03)
- 自定义

文件夹命名:`XX_项目名`(中文,简短明确)。

### A3. 写日志(直接拷贝 ai-os 模板填空)

```bash
mkdir -p "/Users/sunshaocong/Desktop/MacBookpro备份内容/XX_项目名"
cp /Users/sunshaocong/.ai-os/project-templates/project-development-log-template.md \
   "/Users/sunshaocong/Desktop/MacBookpro备份内容/XX_项目名/项目开发日志.md"
```

然后用 Edit 在日志里填空:
- 创建日期 / 最后更新 → 今天
- 「智能体唯一启动入口」节里的项目路径
- 「项目目录地图」(按项目类型预填,见 A4)
- 「当前项目原则」(目标 / 阶段 / 业务底线 / 技术底线 / 不做什么)
- 「当前功能状态」(未开始 = 核心功能列表)
- 「常用文件」(预留路径,缺的标 `[待补充]`)
- 「开发和验证命令」(按技术栈预填,空的标 `[待补充]`)

**不要砍模板任何节**。空字段标 `[待补充]` 留给后续填,但结构完整。

### A5. opt-in 补充文件

每个文件都用 AskUserQuestion 让用户确认是否生成,**不要默认全建**。

| 文件 | 默认推荐场景 | 关键问 |
|-----|------------|-------|
| CLAUDE.md | 开发类且有架构判断 | 这个项目会有需要 Claude 判断的规则吗?没有就不建 |
| AGENTS.md | 开发类且会让 Codex 跑 | 你会让 Codex 在项目里跑修改任务吗?不会就不建 |
| README.md | 准备对外 / 分享 | 这个要给别人看吗?个人用就不建 |
| .gitignore | 会进 git | 要 git 管理吗?不要就不建 |

### A6. 冷启动模拟(交付门槛,不可跳过)

只 `read` 刚生成的「项目开发日志.md」(不读其他文件),试图回答三问:

| 问题 | 应该在日志哪节找答案 |
|------|---------------------|
| Q1. 这个项目要做什么? | 「当前项目原则」→「项目目标」 |
| Q2. 下一步该做什么? | 「当前项目原则」→「当前阶段」+「当前功能状态」→「未开始」 |
| Q3. 怎么验证我做对了? | 「开发和验证命令」 |

**任一答不上(字段空 / 全标 `[待补充]` / 内容含糊),阻止交付**:
- 用 AskUserQuestion 列出空字段
- 用户当场补
- 补完重跑模拟,直到三问全过

通过后才进入 A7。

## 模式 B:补建

cwd 已是项目根(存在「项目开发日志.md」),但缺一些可能需要的文件。

1. 扫描缺失:CLAUDE.md / AGENTS.md / README.md / .gitignore / 日志「目录地图」声明但缺失的子目录
2. 用 AskUserQuestion 多选,让用户选要补哪些
3. 按 A5 的 opt-in 模板生成,**绝不覆盖任何已有文件**
4. 不重做冷启动模拟(那是新建模式的门槛,补建默认信任已有日志)

---

## 模式 C:刷新

cwd 已是项目根,日志的「最后更新」距今 > 30 天(或用户主动要求刷新)。

1. 读日志,提取「当前阶段」「未开始」「已知问题」三节
2. 告诉用户:"距上次更新 X 天,当前阶段还标着『...』,这还准确吗?"
3. 用 AskUserQuestion 引导用户更新关键字段
4. 改完更新「最后更新」日期 + 在「开发记录」末尾追加一行 `YYYY-MM-DD 刷新:...`

---

## 设计原则(行为约束)

1. **日志是 source of truth**,目录从日志的「项目目录地图」拍出来,二者不可漂移
2. **官方模板不二次创作**:直接 `cp /Users/sunshaocong/.ai-os/project-templates/project-development-log-template.md`
3. **默认极简**:除日志外所有文件 opt-in
4. **项目级协议文件 ≤ 20 行**:只做"路径指向 + 加载预算 + 覆盖项"
5. **绝对路径**:`/Users/sunshaocong/.ai-os/...`,不用 `~`(Codex 可能不解析)
6. **接力 idea-to-prompt**:有 Prompt-*.md 就只问差量
7. **冷启动模拟当门槛**:三问不过不交付
8. **补建 / 刷新跨生命周期**:不只 day 1 用得到
