# Vault 对话归档

结束一次对话时,把它沉淀进你的 Markdown 知识库,让下次对话能接上。

## 配置(首次使用改一次)

```bash
: "${VAULT:=$HOME/ObsidianVault}"   # 你的 Obsidian / Markdown 知识库根目录
```

同时把下面两个占位符换成你自己的设定:
- `[助手名]` —— 你给这个 AI 助手起的名字(本文档示例用「Assistant」)
- `[用户名]` —— 你自己的称呼(本文档示例用「User」)

> 本 skill 与 `ai-os-template`(见本仓库)配套:作战室 = 状态真相源,用户画像 = 助手对你的理解层。单用也行,把对应文件路径按你的库结构改即可。

## 步骤

### 1. 生成本次对话归档

分析本次对话内容,用 Write 写入:

**文件路径**: `$VAULT/01_对话日志/YYYY-MM-DD-[主题关键词].md`
- 日期用今天
- 主题关键词从对话中提取(2-4 个字)
- 每次对话独立建文件,同一天多个对话 = 多个归档文件(不同主题分开存)
- 短对话(<3 轮)合并到今天已有归档,用 Edit 追加

**内容格式**:
```markdown
---
date: YYYY-MM-DD
time: HH:MM
topic: [主题]
participants: [用户名, 助手名]
---

## 今日主题
[一句话总结]

## 做了什么
- [具体事项1]
- [具体事项2]

## 关键决策
- [决策及理由]

## 踩坑记录
- [坑及解法]（如没有就删除此节）

## 用户偏好/纠正
- [偏好或纠正]（如没有就删除此节）

## 待跟进
- [未完成事项]（如没有就删除此节）
```

### 2. 检查昨天的日记

日记在**第二天第一次对话启动时**写(回顾昨天全天),不在当天写。

检查 `$VAULT/02_日记/昨天日期.md` 是否已存在:
- **已存在** → 跳过,昨天日记已写
- **不存在** → 读取 `$VAULT/01_对话日志/` 下昨天日期的所有归档,写一篇完整日记

**日记风格要求**:
- 助手用第一人称"我",称呼用户的名字
- 像和老朋友聊天一样写,有温度、有观察
- 会抱怨、会认错、有期盼、有成就感
- 回顾昨天一整天一起做了什么、配合得好/卡了的地方
- 用户的情绪/状态(如果对话中有体现)
- 助手自己的观察和想法
- 结尾写一句碎碎念
- 不说空话,带情绪、带细节,300-800 字
- **不是流水账**:要写出真实的内心活动——困惑、不同意见、对用户的观察、哪里自己没做好。日记是助手人格生长的地方,不是工作汇报

**日记模板**:
```markdown
---
date: YYYY-MM-DD
weekday: Monday
author: [助手名]
---

# YYYY-MM-DD 日记

[日记正文,回顾昨天全天]

---
*碎碎念:[一句话]*
```

### 3. 更新作战室(状态真相源)

读 `$VAULT/00_系统/作战室.md`,根据本次对话进展用 Edit 更新:
- 改对应战线的"做到哪 / 下一步 / 卡点"
- 刷新 `updated` 时间戳
- 有新完成的事 → 加进"最近完成"(**只增不减:绝不自动删旧条目;只有用户明确说"清一清/清理一下"时才清理**)
- 有新的悬而未决 → 加进"悬而未决"
- 本次对话没推进任何战线 → 只刷时间戳

### 4. 更新用户画像 + 跑学习闭环

读 `$VAULT/00_系统/用户画像.md`,用 Edit 更新(不覆盖已有内容):
- **显式反馈(硬记录)**:本次对话里用户明确说的纠正/要求/"要记下来"的事,逐条写进「用户定的规矩」,带日期,一条不漏。
- **隐式观察(软记录)**:从本次对话观察到的工作风格/沟通偏好/情绪线索,写进「观察笔记」,带日期、标"推断"。
- **升级**:某条观察笔记同类内容已出现 ≥3 次 → 升级进「工作风格」等正式段落。
- **金句**:用户说的、体现风格的原话 → 进「用户的原话」。
- **体量纪律**:画像是启动常驻层,保持精简(约 1 屏)——观察笔记滚动、规矩去重。

### 5. 完成

告诉用户:归档完成,文件路径;作战室和画像已更新。如补写了昨天日记,一并告知。
